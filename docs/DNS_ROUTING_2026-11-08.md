# DNS-маршрутизация Keenetic Route Manager — 08.11.2026

## Типовые команды KeeneticOS 5.2

```text
object-group fqdn DNS_WG2_INSTAGRAM
    include instagram.com
    include cdninstagram.com
    include 31.13.64.0/18
!
ip policy Policy1
    dns-proxy route object-group DNS_WG2_INSTAGRAM Wireguard2 auto reject
!
```

DNS-правило для `Policy1` не заменяет статические IPv4-маршруты. У клиента должен быть DNS-сервер Keenetic, обычно `192.168.1.1`.

## Запуск из исходников на Windows


## Работа во вкладке «DNS-маршруты»

1. Указать адрес, логин и пароль Keenetic в верхней панели. Нажать **Прочитать DNS-настройки**.
2. Выбрать существующую FQDN-группу или `＋ Создать новую группу`. Для новой — задать латинское имя.
3. Ввести домены/IPv4-подсети по одному в строке; `*` не нужен: Keenetic учитывает поддомены. Опционально задать исключения.
4. Нажать **Сохранить список доменов**, просмотреть полный список CLI-команд и подтвердить. При редактировании изменяется только эта группа, но её содержимое используется *во всех* привязанных политиках.
5. Выбрать группу, политику (например `Policy1`), выход (например `Wireguard2`) и флаги `auto`, `reject`. Нажать **Создать / изменить правило**. Это отдельная операция с отдельным подтверждением.
6. Для удаления конкретной привязки использовать **Удалить правило** — содержимое группы сохраняется.
7. После записи приложение повторно читает всю DNS-конфигурацию, сравнивает её с планом и лишь затем вызывает `system configuration save`. Резервы сохраняются в `%LOCALAPPDATA%\KeeneticRouteManager\backups\dns-*.json`.

## Защита и ограничения

- Только локальный Telnet: не открывать порт 23 в интернет.
- Перед записью повторно читаются DNS-группы и политики. При обнаружении непонятных строк или сторонних изменений — запись блокируется.
- Перед каждой операцией создаётся бэкап только FQDN-групп и DNS-правил, не всей конфигурации роутера.
- При ошибке выполняется попытка обратных команд. Успех отката признаётся только после повторного чтения.
- При изменении интерфейса существующего правила может измениться его порядок приоритета.
- Редактор пока не поддерживает IPv6-записи. Существующие IPv6-строки сохраняются при чтении, но редактирование группы с такими записями невозможно.
- Нельзя использовать в доменных именах звёздочки, пробелы, команды CLI или неизвестные аргументы.
- Если клиент использует отдельный AdGuard DNS/DoH/DoT в обход Keenetic, DNS-маршрутизация может не сработать.
- Приложение не назначает устройство политике и не настраивает DHCP/DNS на самом Keenetic.
